# Anabiosis — архитектура (черновик)

Технический стек и структура проекта. Дизайн игры — см. [[game_design]].

## Стек

- **C# + MonoGame** — совершенно новый проект, не развитие старого прототипа `SpaceShipGame` (WinForms) и не другой движок (Godot и т.п. не выбраны).

## Структура решения

Один solution, 4 проекта:

- **Anabiosis.Shared** — общие модели данных и сетевой протокол: `Ship`, `Room`, `Character`, `ShipSystem` (реактор/щиты/etc.), `Wire`, `Item`, `Sector`, `Faction`, `Quest`, DTO для сетевых сообщений. Используется и сервером, и клиентом, чтобы не дублировать структуры.
- **Anabiosis.Server** — авторитетная симуляция: физика корабля, урон, распределение энергии, ИИ ботов/врагов, квесты, галактика. Headless (консоль), без рендера.
- **Anabiosis.Client** — MonoGame: рендер, ввод, HUD, интерполяция состояния с сервера. Без игровой логики — только читает состояние и шлёт команды.
- **Anabiosis.Tests** — юнит-тесты на Shared/Server-логику (протокол, распределение энергии, урон), без сети/рендера.

## Клиент-сервер

Клиент-серверная архитектура с первого дня (см. фазы разработки в game_design.md). Соло-режим — это клиент, который сам поднимает у себя встроенный сервер (in-process host) и подключается к нему как обычный клиент. Соло и мультиплеер идут по одному и тому же коду симуляции, без дублирования логики.

## Данные vs системы (внутри Server/Shared)

Не полноценный ECS-фреймворк — оверкилл для масштаба хобби-проекта (десятки, не тысячи сущностей). Вместо этого простое разделение:
- **Компоненты** (данные) на объектах: `PowerComponent`, `DamageComponent`, `HealthComponent` и т.д.
- **Системы** (логика), обновляющие компоненты по тику: `PowerDistributionSystem`, `RepairSystem`, `BreachSystem` и т.д.

## Конвенции кода

- Не допускать разрастания файлов: код разбивается на подразделы/файлы по темам (например, partial-классы по функциональности), а не собирается в один большой файл на тысячи строк — как уже сделано в прототипе `SpaceShipGame` (`GameForm.cs` → `GameForm.Combat.cs`, `.Render.cs`, `.Inventory.cs` и т.д.).

## Открытые вопросы

- **Сетевая библиотека**: сырой TCP (как в прототипе SpaceShipGame) vs готовая игровая сетевая библиотека (например LiteNetLib поверх UDP) — решение отложено до этапа реализации сети.
- Формат данных для планировки кораблей (комнаты/стены/проёмы/точки размещения систем): захардкожено в коде, JSON, или редактор уровней (тайлмап, как в Tiled) — не обсуждали.
- Тип синхронизации сервер→клиент (полное состояние vs дельты, интерполяция/предсказание на клиенте) — не обсуждали.
- Формат сохранений похода (галактика, корабль, экипаж, репутация) — не обсуждали.
